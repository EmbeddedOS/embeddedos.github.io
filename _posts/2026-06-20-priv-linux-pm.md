## Power management in a computing system

Three major components:

- Hardware: responsbile for providing configuration interfaces ("knobs") so the OS can properly manage the power consumption.
- Kernel: via device drivers and subsystems, it is responsible for exposing power management abstractions to user space applications.
- User: Via abstractions provided by the kernel, they are responsible for implementing a policy for power management.

## The role of hardware

The hardware is the foundation upon which sw based pm strategies are built, so an energy-efficient hw design is a very important strategy to reduce power consumption.

- Select inherently energy-efficient hw components.
- Select hw components that provide configuration interfaces for PM.
- Design circuits that minimize electrical losses and reduce power consumption.

## What is power?

## Power management techniques

Every power management technique can be put into 2 major categories: *idle* and *active* pm.

- An idle pm technique will help to save the power when the system is not doing any work (shutting down some hardware components) -> trade off between power reduction and latency.
- An active power management technique will help to save power when the system is doing some work (e.g: scaling down the CPU frequently). -> trade off bw power reduction and performance.

## HW knobs for idle PM

- The main strategy for idle pm is to turn hw components off.
- CPU idle states (also called C-states) make it possible to put the CPU into a low-power mode when it is not actively being used.
- Clock gating is a power-saving technique that reduces power consumption by selectively disabling (gating) the clock signal to specific portions of a circuit when they are not actively processing data.
- Power domain (PD) is a modern SoC feature that enables finer-grained power management by selectively powering down multiple (unused or idle) components at the same time.

## HW knobs for active PM

- The main strategy for active pm is to scale down the frequency/voltage of hw components.
- **Dynamic Voltage and Frequency Scaling (DVFS)** is a feature available in many processors and other components that makes it possible to adjust the operating frequency and voltage, thus reducing power consumption.
- **Thermal management** is a process of monitoring the heat generated by a hw component (reading thermal sensors) and taking some action to prevent overheat (turning the fans on).
- **Battery management** is a process to monitor the battery's state and take some action to optimize battery life.

## How to control these knobs?

- Processors may provide special registers and instructions that are used to change power states or manage energy efficiency (WFI instruction on ARM).
- Hardware components might expose an interface for pm in memory mapped registers (e.g setting a bit in a register turns off the clock of a peripheral).
- Some hw platforms might provide a fw interface for pm (e.g. ACPI on x86).
- Dedicated external chips might provide features for pm (e.g. PMIC).
- In the end, the interfaces and features available for pm will depend on the processor architecture and hw design.

## Linux Kernel - features and subsystems for pm

### PM in the Linux Kernel

The Linux kernel provides a complete infrastructure for pm:

- **Idle PM**: infrastructure to be used when the system (or part of it) is idle.
- **Active PM**: infrastructure for when these is some processing happening.

The PM infrastructure in the Linux Kernel is implemented in different subsystems, exposing pm configuration interfaces to user-space applications through interfaces like **sysfs**.
It is flexible and standardized, so Linux can run efficiently on a wide array of hw, from low-power embedded devices to high-performance servers.

### System-wide PM

System-wide pm is designed to reduce power comsumption by moving the entire system into lower-power modes when there is nothing to be done.

There are four main system-wide power states:

- Suspend to idle: sw-based suspend, timer interrupts are disabled, user space is frozen, and I/O devices enter low-power states.
- Standby: besides suspend to idle, nonboot CPUs are taken offline.
- Suspend to RAM: everything in the system is put into a low-power state, except for memory, which is placed into self-refresh mode to retain its contents.
- Suspend to disk: also known as "hibernate", this state writes the contents of RAM to persistent storage before powering off most of the system.

The 4 modes:

```bash
$ cat /sys/power/state
freeze standby mem disk
```

To config **Suspend to RAM**:

```bash
echo mem > sys/power/state
```

The shell should be shutdown after that.
